ReShiki includes the drawing and chemistry tools. **You do not need to install Python, RDKit, or uv.** There is no chemistry download or environment setup on first launch. See [what changed in 0.16.0](/developer/changes-0.16/).

## 1. Download and open

[Download the latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest), recommended for everyday work. Choose the package for your computer below.

See the [license scope](https://github.com/Ameyanagi/ReShiki/blob/main/LICENSE)

Downloaded apps include these texts in their `Licenses` directory
(`ReShiki.app/Contents/Resources/Licenses` on macOS).

| Your computer     | Download ends in          | Install                                         |
| ----------------- | ------------------------- | ----------------------------------------------- |
| Apple Silicon Mac | `macos-arm64.dmg`         | Open, then drag **ReShiki** to **Applications** |
| Intel Mac         | `macos-x64.dmg`           | Open, then drag **ReShiki** to **Applications** |
| Windows x64       | `windows-x64-setup.exe`   | Run setup, then open **ReShiki** from Start     |
| Windows ARM       | `windows-arm64-setup.exe` | Run setup, then open **ReShiki** from Start     |
| Linux x64         | `linux-x64.tar.gz`        | Extract, then run `reshiki`                     |
| Linux ARM         | `linux-arm64.tar.gz`      | Extract, then run `reshiki`                     |

Windows setup installs for your account. Portable ZIP downloads are also
available; keep a portable download’s extracted contents together. Windows may
warn before running setup: the [code signing policy](/developer/code-signing-policy/)
gives each platform’s signing status. See also the [privacy policy](/developer/privacy-policy/).

Upgrading from an earlier version? Open your existing `.reshiki` and `.moruno` drawings normally. Templates, assistant preferences, and recovery drafts are copied on first launch; the originals stay in place. New drawings use `.rsk`.

### Your data folder

ReShiki keeps its settings, templates, recovery drafts, GitHub working copies
and update downloads in one folder: `~/.reshiki/` on macOS and Linux, and
`%LOCALAPPDATA%\reshiki\ReShiki\data\` on Windows. Click **ReShiki** at the top
left to see it in **About ReShiki**; **Open** shows it in your file manager.

What GitHub sent, so a repository opens again without downloading it, is
kept in `cache/github/` in that folder on macOS and Linux, and in
`%LOCALAPPDATA%\reshiki\ReShiki\cache\github\` on Windows: up to 200 MB,
one folder per GitHub account. You can delete it at any time; ReShiki
downloads what it needs again.

Earlier versions used `~/Library/Application Support/dev.reshiki.ReShiki/` on
macOS and `~/.local/share/reshiki/` (or `$XDG_DATA_HOME/reshiki/`) on Linux.
ReShiki moves that folder to `~/.reshiki/` the first time it starts. If it
cannot, it keeps using the old folder and says why in the status bar.

### Uninstall

:::caution
GitHub drawings you have not sent live only in the data folder, in `github/`.
Send them before you delete it.
:::

**macOS and Linux**

1. In ReShiki, note the data folder in **About ReShiki**, then open the GitHub
   menu and choose **Sign out**. The sign-in is in the Keychain (macOS) or the
   Secret Service keyring (Linux), not in `~/.reshiki/`. If the app is already
   gone, delete the `dev.reshiki.ReShiki.github` item in Keychain Access, or
   run `secret-tool clear service dev.reshiki.ReShiki.github`.
2. Delete the app: **ReShiki** in **Applications**, or the extracted folder on
   Linux.
3. Delete `~/.reshiki/`. If **About ReShiki** named another data folder (the
   old one, when ReShiki could not move it), delete that one too.

**Windows**

1. Open **Settings → Apps**, select **ReShiki**, and choose **Uninstall**. This
   removes the app and its shortcuts and keeps your data. For a portable
   download, delete the extracted folder.
2. Delete `%LOCALAPPDATA%\reshiki\`.
3. If you were signed in to GitHub, open **Credential Manager → Windows
   Credentials** and remove `dev.reshiki.ReShiki.github`.

Update downloads (`updates/`) and the GitHub cache (`cache/`) are in
`~/.reshiki/` or `%LOCALAPPDATA%\reshiki\`, so deleting that folder removes
them too. Earlier versions left a hidden `.reshiki-update-…` folder next to the
app: in **Applications** on macOS, or beside the installed
or extracted folder on Linux and Windows (`%LOCALAPPDATA%\Programs\` for the
setup program's install). ReShiki removes those when it starts; if you
uninstall an earlier version and one remains, delete it too.

Starting with 0.9.0, Mac supports Apple Silicon and Intel on macOS 14+. Windows requires Windows 10/11 on x64 or Windows 11 on ARM64. Linux builds target Ubuntu 22.04+ on x64 and 24.04+ on ARM.

### Nix

On Linux (x64 and ARM) and Apple Silicon Macs, you can build ReShiki from source with [Nix](https://nixos.org):

```sh
nix run github:Ameyanagi/ReShiki
nix profile install github:Ameyanagi/ReShiki
```

Update with `nix profile upgrade`; the in-app updater only replaces downloaded releases. On Linux outside NixOS, ReShiki needs your system's GPU driver; if it reports that no graphics adapter was found, start it through [nixGL](https://github.com/nix-community/nixGL). On a Mac, the package contains **ReShiki.app** and the `reshiki` command: nix-darwin and home-manager add the app to your Applications folder; with `nix profile install`, find it in `~/.nix-profile/Applications`. The DMG remains the signed, notarized Mac app.

### Linux desktop launchers

ReShiki identifies its Wayland and X11 windows as `reshiki`. If you create a
launcher for a self-built or portable app, name it `reshiki.desktop` and set
`StartupWMClass=reshiki` so the desktop can group its windows with the launcher.
Its `Icon` entry must name an installed icon. The Nix package installs a matching
launcher and icon.

### File compatibility

Older drawings open in ReShiki 0.16.0, and most drawings it saves also open in
0.13.1, 0.14.0 and 0.15.0. A property caption under a molecule (**Show
properties**), with or without a name line, needs 0.16.0. If you share files
with someone on an older version, keep a copy saved by that version. The
[file compatibility table](/developer/changes-0.16/#file-compatibility) lists
which features need which version.

## Try it in your browser

[Open the browser preview](/demo/) to try ReShiki without installing it.
Drawing runs in the browser, and your files stay on your computer. The editor's
JavaScript and WebAssembly have an estimated first download of 9 MB compressed
(gzip -9). The naming worker loads on demand; Japanese, Korean or Chinese text
may also download a font from jsDelivr; see the
[privacy policy](/developer/privacy-policy/#website-and-external-links).

The browser preview is not the full app. Use the [desktop app](#1-download-and-open)
whenever you can. In the browser:

- Naming and NMR prediction work, but there is no assistant, printing, or
  Office and LibreOffice integration. 3D models work, but the page pauses
  while one is computed.
- Copy puts a picture and SMILES on the clipboard, and Paste takes ReShiki
  drawings, chemical text and pictures, but not PDF, CDX or ChemDraw's own
  clipboard data; see [Clipboard](/developer/clipboard/#in-the-browser). Settings,
  templates and recovery drafts stay in the browser's storage for this site.
- Shortcuts are the desktop app's, with ⌘ on a Mac, except New, Close tab and
  switching tabs, which the browser keeps: use Alt+N, Alt+W and Alt+] / Alt+[
  (⌃N, ⌃W and ⌃] / ⌃[ on a Mac). Long cleanups or imports pause the page.

## Nightly builds

Nightly builds are optional prereleases for testing upcoming changes from `main`. For everyday work, use the [latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest).

To try a nightly, open [GitHub Releases](https://github.com/Ameyanagi/ReShiki/releases), choose a release named **Nightly** with the **Pre-release** label, and use its operating-system and architecture download table. New nightlies include macOS DMG/ZIP downloads for Apple Silicon, Windows setup/ZIP downloads and Linux tar.gz archives, signed as the [code signing policy](/developer/code-signing-policy/) describes.

Installers replace the existing ReShiki installation. To retain Stable, choose a portable archive and extract it into a separate folder, keeping its contents together. Use copies of drawings when testing. Older nightlies may offer only unsigned portable archives; the release notes identify the available packages.

Nightly builds are not made for Intel Macs. On an Intel Mac, use the stable release.

The all-releases page includes stable releases and nightlies; a newer nightly can appear above stable. The **Latest** label and the stable download links identify the stable release.

## Updates

:::note[Linux upgrades from 0.9.1 and earlier]
Download and extract the 0.10.0 Linux archive manually, then start its `reshiki` executable. Older updaters expect a separate chemistry helper; 0.10.0 packages contain one executable. Subsequent updates use the new layout.
:::

The channel selector is included in ReShiki 0.10.0. If you use 0.9.1 or earlier, update to the [latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest) first.

Click **ReShiki** at the top left → **Check for updates**. Choose **Stable** (the default) or **Nightly** in the update window. ReShiki remembers your choice and checks that channel once a day; turn off **Check automatically** here if you prefer. Changing channels starts a fresh check without turning automatic checks back on.

<Screenshot
  src="/doc-images/nightly-installers/nightly.png"
  alt="ReShiki’s Nightly update window offers a manual download and links portable archives through Release notes."
/>

On **Stable**, when an update is available, save your drawings and choose
**Update and restart**. ReShiki then:

- waits until unsaved drawings, atom-label edits, assistant drafts and
  assistant input or attachments are resolved;
- downloads the matching release and verifies its checksum (and, on macOS, the
  developer signature);
- installs it and reopens every saved tab in its original order.

The download goes to `updates/<version>/` in your
[data folder](#your-data-folder) and is verified there. ReShiki removes it once
the update is installed, and removes whatever an interrupted update left the
next time it starts, so `updates/` normally holds only the last check's result
(`stable.json` or `nightly.json`). When the data folder is on another disk than
the app, the verified app is first copied to a hidden `.reshiki-update-…` folder
next to the app, so the swap is still a single rename.

If a download or verification fails, the running app stays in place. On macOS
and Linux, if the install itself fails, ReShiki puts the previous version back
and reopens it.
**Release notes** opens the release page. Automatic checks never install an
update without your click.

On **Nightly**, choose **Download nightly ↗** to download the DMG or Windows setup for your operating system and architecture when available. Older nightlies fall back to ZIP; Linux uses tar.gz. Installation remains manual. **Release notes** opens the selected build’s table with both installer and portable options, notes and checksums. Nightlies do not use the automatic stable installer. On an Intel Mac, **Nightly** reports that no nightly is made for it; choose **Stable**. Older app versions label this button **Download portable ↗** and always choose an archive.

Switching channels offers the latest release in the chosen channel even when its version number is lower. This lets stable users try a nightly with the same base version, and nightly users return to the latest stable release. Within a channel, only newer versions are offered.

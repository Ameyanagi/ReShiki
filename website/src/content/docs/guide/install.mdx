ReShiki includes the drawing and chemistry tools. **You do not need to install Python, RDKit, or uv.** There is no chemistry download or environment setup on first launch. See [what changed in 0.9](/developer/changes-0.9/).

## 1. Download and open

[Download the latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest), recommended for everyday work. Choose the package for your computer below.

Third-party components and code adaptations retain their respective terms.
See the [license scope](https://github.com/Ameyanagi/ReShiki/blob/main/LICENSE)
and [third-party notices](https://github.com/Ameyanagi/ReShiki/blob/main/NOTICE).
Downloaded apps include these texts in their `Licenses` directory
(`ReShiki.app/Contents/Resources/Licenses` on macOS).

| Your computer     | Download ends in          | Install                                         |
| ----------------- | ------------------------- | ----------------------------------------------- |
| Apple Silicon Mac | `macos-arm64.dmg`         | Open, then drag **ReShiki** to **Applications** |
| Intel Mac         | `macos-x64.dmg`           | Open, then drag **ReShiki** to **Applications** |
| Windows x64       | `windows-x64-setup.exe`   | Run setup, then open **ReShiki** from Start     |
| Windows ARM       | `windows-arm64-setup.exe` | Run setup, then open **ReShiki** from Start     |
| Linux x64         | `linux-x64.tar.gz`        | Extract, then run `reshiki`                     |
| Linux ARM         | `linux-arm64.tar.gz`      | Extract, then run `reshiki`                     |

Windows setup installs for your account. Mac downloads are signed and notarized; Windows downloads are unsigned. Portable ZIP downloads are also available. Keep a portable download’s extracted contents together.

Read the [Code signing policy](/developer/code-signing-policy/) and
[privacy policy](/developer/privacy-policy/). SignPath access is provisioned;
the release certificate and Windows signing activation are pending. Existing
Windows downloads are unsigned.

To uninstall on Windows, open **Settings → Apps**, select **ReShiki**, and choose
**Uninstall**. Uninstalling removes the installed application and its shortcuts;
it preserves your drawings, preferences, and recovery drafts. For a portable
download, remove the extracted application folder when you no longer need it.

Upgrading from an earlier version? Open your existing `.reshiki` and `.moruno` drawings normally. Templates, assistant preferences, and recovery drafts are copied on first launch; the originals stay in place. New drawings use `.rsk`.

Starting with 0.9.0, Mac supports Apple Silicon and Intel on macOS 14+. Windows requires Windows 10/11 on x64 or Windows 11 on ARM64. Linux builds target Ubuntu 22.04+ on x64 and 24.04+ on ARM.

## Nightly builds

Nightly builds are optional prereleases for testing upcoming changes from `main`. For everyday work, use the [latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest).

To try a nightly, open [GitHub Releases](https://github.com/Ameyanagi/ReShiki/releases), choose a release named **Nightly** with the **Pre-release** label, and use its operating-system and architecture download table. New nightlies include signed, notarized macOS DMG/ZIP downloads, Windows setup/ZIP downloads, and Linux tar.gz archives. Windows and Linux packages remain unsigned.

Installers replace the existing ReShiki installation. To retain Stable, choose a portable archive and extract it into a separate folder, keeping its contents together. Use copies of drawings when testing. Older nightlies may offer only unsigned portable archives; the release notes identify the available packages.

The all-releases page includes stable releases and nightlies; a newer nightly can appear above stable. The **Latest** label and the stable download links identify the stable release.

## Updates

:::note[Linux upgrades from 0.9.1 and earlier]
Download and extract the 0.10.0 Linux archive manually, then start its `reshiki` executable. Older updaters expect a separate chemistry helper; 0.10.0 packages contain one executable. Subsequent updates use the new layout.
:::

The channel selector is included in ReShiki 0.10.0. If you use 0.9.1 or earlier, update to the [latest stable release](https://github.com/Ameyanagi/ReShiki/releases/latest) first.

Click **ReShiki** at the top left → **Check for updates**. Choose **Stable** (the default) or **Nightly** in the update window. ReShiki remembers your choice and checks that channel once a day; turn off **Check automatically** here if you prefer. Changing channels starts a fresh check without turning automatic checks back on.

<Screenshot
  src="/doc-images/nightly-installers/nightly.png"
  alt="ReShiki’s Nightly update window offers a manual download and links portable archives through Release notes."
/>

On **Stable**, when an update is available, save your drawings and choose **Update and restart**. ReShiki downloads the matching release, verifies its checksum (and the developer signature on macOS), installs it, and reopens every saved tab in its original order, with the previously front tab in front again. Installation waits for unsaved drawings, pending atom-label edits, assistant drafts and unfinished text/image input to be resolved. Clear the assistant input or attachment when finished with it. If a download or verification fails, the running app stays in place. **Release notes** opens the release page. Automatic checks never install an update without your click.

On **Nightly**, choose **Download nightly ↗** to download the DMG or Windows setup for your operating system and architecture when available. Older nightlies fall back to ZIP; Linux uses tar.gz. Installation remains manual. **Release notes** opens the selected build’s table with both installer and portable options, notes and checksums. Nightlies do not use the automatic stable installer. Older app versions label this button **Download portable ↗** and always choose an archive.

Switching channels offers the latest release in the chosen channel even when its version number is lower. This lets stable users try a nightly with the same base version, and nightly users return to the latest stable release. Within a channel, only newer versions are offered.

Writing inputs and reading outputs works in every ReShiki build, Windows included. It does not need the xTB engine.

## Write an input file

ReShiki writes a text input for another program from the molecule's 3D model. Nothing runs in ReShiki.

1. Select one molecule.
2. Open **Export → Input for Gaussian / ORCA / GAMESS…**, or search the command palette for **Export input for Gaussian / ORCA / GAMESS…**. If the molecule has no 3D model, **Generate 3D model** makes one with MMFF94s first; for structures MMFF94s cannot handle, such as many metal complexes, make or open a 3D model another way.
3. Choose the **Program**: **Gaussian**, **ORCA**, **GAMESS** or **XYZ** (coordinates only).
4. Pick a **Template**, or set **Method**, **Basis** and **Task** yourself. The built-in templates are `B3LYP-D3BJ/def2-SVP opt+freq`, `r2SCAN-3c opt+freq` (ORCA only) and `HF/6-31G(d) single point`. **Save as template…** keeps your own.
5. Check **Charge** and **Multiplicity**. They come from the charges and radicals drawn on the molecule, not from an xTB calculation: if you set another charge or spin there, or opened a file whose ion or spin state the drawing could not show, enter it here. Then set **Cores**, **Memory (GB)**, **Title** and **Extra keywords**.
6. Read the **Preview**: it is the exact file text. **Copy** puts it on the clipboard; **Save** writes the file, named after the molecule (`aspirin.gjf`, `aspirin.inp`).

**Geometry** shows which coordinates go into the file: the molecule's current 3D model. After an applied xTB optimization, that is the optimized geometry.

### Tasks

| Task                 | Gaussian                           | ORCA                                                                                          | GAMESS            |
| -------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------- | ----------------- |
| Single point         | yes                                | yes                                                                                           | yes               |
| Optimize, Opt + freq | yes                                | yes                                                                                           | yes               |
| Transition state     | `Opt=(TS,CalcFC,NoEigenTest) Freq` | `OptTS Freq` (`OptTS NumFreq` for methods without analytic frequencies, such as MP2 or DLPNO) | `RUNTYP=SADPOINT` |
| IRC                  | yes                                | yes                                                                                           | —                 |

The transition-state inputs start from the 3D model as the guess, and ORCA computes its own first Hessian. QST2, QST3 and NEB-TS are listed but greyed: they need the reactant and product of a [transition-state search](/guide/calculation-transition-states/), which is in progress, as is reading the xTB Hessian into ORCA from a `.hess` file.

GAMESS runs one task per job and uses its built-in basis sets: `6-31G(d)` (or `6-31G*`), `6-31G` and `STO-3G`. Other bases, such as the template's `def2-SVP`, are refused and **Copy** and **Save** stay off; choose one of these after switching to GAMESS.

## Open an output file

**Open** reads these files:

| File                                           | What ReShiki reads                                                           |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| Gaussian `.log`, `.out`                        | Every job: geometries, energies, frequencies, orbital energies, how it ended |
| ORCA `.out`                                    | The same                                                                     |
| Gaussian `.fchk`, Molden `.molden`             | Geometry, orbitals, frequencies                                              |
| XYZ                                            | The first frame; the status bar says when the file has more                  |
| SDF                                            | Every record, laid out side by side as space allows                          |
| Gaussian `.gjf`/`.com`, ORCA and GAMESS `.inp` | The geometry in the input                                                    |

For a Gaussian or ORCA output, ReShiki opens the final geometry of the last job that has a geometry and ended normally, as a 3D model in a new, unsaved drawing named after the file. If there is none, it opens the last job that has a geometry, even a failed or cut-off one. The status bar names the job, its method and how it ended, for example `Final geometry of job 3 of 3: Frequencies · RB3LYP/6-31G, Normal termination`, so you can tell which one you got.

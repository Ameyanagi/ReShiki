Writing inputs and reading outputs works in every ReShiki build, Windows included. It does not need the xTB engine.

## Write an input file

ReShiki writes a text input for another program from the molecule's 3D model. Nothing runs in ReShiki.

1. Select one molecule.
2. Open **Export → Input for Gaussian / ORCA / GAMESS…**, or search the command palette for **Export input for Gaussian / ORCA / GAMESS…**. If the molecule has no 3D model, **Generate 3D model** makes one with MMFF94s first.
3. Choose the **Program**: **Gaussian**, **ORCA**, **GAMESS** or **XYZ** (coordinates only).
4. Pick a **Template**, or set **Method**, **Basis** and **Task** yourself. The built-in templates are `B3LYP-D3BJ/def2-SVP opt+freq`, `r2SCAN-3c opt+freq` (ORCA only) and `HF/6-31G(d) single point`. **Save as template…** keeps your own.
5. Check **Charge** and **Multiplicity** (from the drawing, or from the last calculation), **Cores**, **Memory (GB)**, **Title** and **Extra keywords**.
6. Read the **Preview**: it is the exact file text. **Copy** puts it on the clipboard; **Save** writes the file, named after the molecule (`aspirin.gjf`, `aspirin.inp`).

**Geometry** shows which coordinates go into the file. After an xTB optimization the 3D model holds the optimized geometry, so the input starts from it.

### Tasks

| Task                 | Gaussian                           | ORCA                  | GAMESS            |
| -------------------- | ---------------------------------- | --------------------- | ----------------- |
| Single point         | yes                                | yes                   | yes               |
| Optimize, Opt + freq | yes                                | yes                   | yes               |
| Transition state     | `Opt=(TS,CalcFC,NoEigenTest) Freq` | `OptTS Freq`          | `RUNTYP=SADPOINT` |
| QST2, QST3           | yes, with reactant and product     | —                     | —                 |
| IRC                  | yes                                | yes                   | —                 |
| NEB-TS               | —                                  | yes, with the product | —                 |

QST2, QST3 and NEB-TS need the reactant and product of a [transition-state search](/guide/calculation-transition-states/), which is in progress. With an xTB Hessian, the ORCA transition-state input reads it from a `.hess` file written beside the input, which saves ORCA's first, most expensive Hessian.

GAMESS runs one task per job and has built-in basis sets only; the dialog warns when a choice does not fit.

## Open an output file

**Open** reads these files:

| File                                           | What ReShiki reads                                                           |
| ---------------------------------------------- | ---------------------------------------------------------------------------- |
| Gaussian `.log`, `.out`                        | Every job: geometries, energies, frequencies, orbital energies, how it ended |
| ORCA `.out`                                    | The same                                                                     |
| Gaussian `.fchk`, Molden `.molden`             | Geometry, orbitals, frequencies                                              |
| XYZ (also multi-frame), SDF                    | Geometries                                                                   |
| Gaussian `.gjf`/`.com`, ORCA and GAMESS `.inp` | The geometry in the input                                                    |

The final geometry of the last job that ended normally opens as a 3D model in a new, unsaved drawing named after the file. The status bar names the job, its method and how it ended, for example `Final geometry of job 3 of 3: Frequencies · RB3LYP/6-31G, Normal termination`. A failed or cut-off job never lends its geometry to the energy of another job.

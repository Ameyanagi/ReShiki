# Unreleased changes

- **Under review — Faster scene building on large drawings:** building the drawing's shapes after an edit now looks atoms and their bonds up in an index made once per build, instead of scanning the whole drawing for every atom label, double bond, bond end and ring circle. On 7,700 atoms (the shortcut examples tiled 16 times) a build takes about 160 ms instead of about 600 ms, and on 1,900 atoms about 21 ms instead of about 40 ms. The drawing, labels and exports are unchanged. · @Ameyanagi.
- **Under review — Zooming no longer re-outlines every label each frame:** the canvas outlines text at quarter-octave zoom steps and scales the small remainder, and a full text cache now drops the outlines used least recently instead of all of them. In the headless benchmark a zoom frame of the 483-atom shortcut gallery takes 1.5 ms instead of 11 ms and allocates 1.6 MB instead of 10 MB. At zooms of ½×, 1×, 2× and the other quarter-octave steps text draws pixel for pixel as before; between steps, glyph edges can move by about one pixel because hinting is done at the nearest step. · @Ameyanagi.
- **Under review — Faster 2D layout for long chains and polymers:** laying out a long chain or polymer from SMILES, a name or a structure without coordinates is about 3–10× faster: polystyrene with 75 units takes 0.4 s instead of 2.8 s, and poly-alanine with 200 units 0.4 s instead of 3.8 s, with the same drawing as before. Polystyrene with 100 units now lays out instead of failing with "Depiction collision work or storage limit exceeded"; a still larger molecule whose overlap repair runs out of work keeps its layout before that repair instead of failing. · @Ameyanagi.
- **Under review — The browser editor no longer holds saved fonts in memory:** fonts the browser editor keeps for later visits, such as the Japanese and Korean fallbacks, now stay in browser storage until text needs them instead of being loaded into the editor's memory on every visit. With Noto Sans JP and KR saved (9.2 MB), the editor starts in 41.4 MiB instead of 59.0 MiB, and after showing Japanese and Korean text it holds 59.1 MiB instead of 67.9 MiB (76.9 MiB on the visit that downloads them). The text looks the same and no font is downloaded again; fonts saved by earlier versions are used as before. The browser editor also drops the desktop worker allocator, which had no limit to enforce there, so its WebAssembly is 140 KB smaller. The desktop app is unchanged. · @Ameyanagi.
- **Under review — Faster redraws when zoomed in on large drawings:** the canvas now skips bonds, shapes, lines and label halos that lie entirely outside the window, part by part, before turning them into triangles, instead of processing the whole drawing on every redraw. Zoomed in on a drawing of 7,700 atoms, drawing the scene takes about 1 ms instead of 8–12 ms. What appears on screen is unchanged, pixel for pixel; exports and printing do not use the canvas and are unchanged. · @Ameyanagi.
- **Under review — Faster edits on drawings with many group labels:** moving or editing atoms in a drawing with many collapsed groups (such as Boc, OTBS or CO2Et) no longer rescans every bond and atom once per group to decide which groups stay collapsed. A move in a drawing with 7,700 atoms and 256 group labels now commits in about 17 ms instead of 50 ms; the check itself drops from 38 ms to about 4 ms. Which groups stay collapsed or open is unchanged. · @Ameyanagi.
- **Under review — Browser preview docs match the browser editor:** the npm README, the install guide and the home page no longer say that 3D needs the desktop app: 3D models work in the browser editor but pause the page while they compute. The README no longer says that drawing styles, themes, templates and pictures cannot be loaded from files or that Insert cannot insert files, and the install guide no longer says that copy and paste carry text only or that there are no recovery drafts. All three now say that naming and NMR prediction work in the browser editor. · [Issue #434](https://github.com/Ameyanagi/ReShiki/issues/434) · @Ameyanagi.
- **Under review — The npm editor recovers from a failed load, reports a bad `src` and fits under a strict CSP:** after the editor's WebAssembly fails to download once, the next `mount()` tries again instead of rejecting with the same error until the page is reloaded. `<reshiki-editor src>` that answers with an HTTP error, such as a 404 page, now fires `error` with "Could not load <src>: HTTP 404" instead of reading the page as a drawing and leaving an unhandled rejection. On a page whose Content-Security-Policy keeps `style-src` strict (no `'unsafe-inline'`), the editor now fills its element instead of shrinking to a 300×150 canvas in the corner, since the canvas and the input-method textarea are styled through the CSSOM. The package README gains a Content Security Policy section listing what the editor needs. The demo and the desktop app are unchanged. · [Issue #431](https://github.com/Ameyanagi/ReShiki/issues/431) · @Ameyanagi.
- **Under review — Faster hover on large drawings:** finding the atom label under the pointer, which runs on every mouse move, now skips atoms whose labels cannot reach the pointer instead of laying out every label in the drawing. On 7,700 atoms (the shortcut examples tiled 16 times) each check takes about 1 ms or less instead of 0.7–1.0 s, and on 1,900 atoms 0.1–0.3 ms instead of 17–20 ms. What the pointer picks, in any installed font, and how labels look are unchanged. · @Ameyanagi.
- **Under review — Faster unsaved-changes check on large drawings:** the unsaved-changes dot in the window title and the tab strip now compares the drawing with the saved one once per update instead of three times, and the comparison no longer copies every atom and bond, so on a 7,700-atom drawing each update spends about 0.3 ms on it instead of about 6.5 ms. Undoing back to the saved drawing still clears the dot, and live previews such as Edit hues show it while they differ from the saved drawing. · @Ameyanagi.
- **Under review — The browser preview shows its progress and says why it cannot start:** [reshiki.com/demo](https://reshiki.com/demo/) now shows a progress bar while the 23 MB editor downloads instead of a blank page, and a message with a Reload button and a desktop-app link when the browser has neither WebGPU nor WebGL 2 or the download fails. The page preloads the editor's JavaScript and WebAssembly, so they download together instead of one after the other. The page is `packages/editor/examples/demo.html`. · [Issue #433](https://github.com/Ameyanagi/ReShiki/issues/433) · [Issue #434](https://github.com/Ameyanagi/ReShiki/issues/434) · @Ameyanagi.
- **Under review — R/S and E/Z labels on long stereo chains use far less memory:** working out stereo labels now keeps one centre's ranking data at a time instead of all of them at once, so a chain with 300 stereocentres peaks at about 6 MB instead of 76 MB. Chains with 400 or more centres, which used to fail with "CIP resource limit exceeded" and show no labels, are now labelled. The labels themselves are unchanged. · @Ameyanagi.
- **Under review — Faster copy and export:** copying a drawing as PDF or a picture, and exporting PNG, PDF or Office SVG, no longer loads and scans every installed font for each copy or export, and the default label font (Arial) is read from disk once instead of being reopened for every piece of text. On the shortcut examples (483 atoms) a PDF copy or export takes about 40 ms instead of about 350–550 ms; on 7,700 atoms (the examples tiled 16 times) about 2.4 s instead of 8.5–11 s. The files are the same as before. · @Ameyanagi.
- **Under review — Automatic in the alignment menu for atom labels:** the Style bar's alignment menu now offers **Automatic**, **Left**, **Center**, **Right** and **Stacked above** when atom or group labels are selected, with Automatic checked by default, as ChemDraw's Text menu does. Automatic reads the label from its bonds (HO on a left-pointing bond, OH on a right-pointing one, MeO and OMe), and choosing it again returns a label forced to Left, Center or Right to automatic. It now covers element labels (Left reads OH, Right HO) and free text labels as well as groups, and the separate group-only **Auto / above** list is gone. The **Edit atom label** dialog gains an **Alignment** list, Automatic by default, that applies with the label. Captions keep Left / Center / Right / Justify. - **Under review — Name ↔ structure conversion in the browser editor:** **Import → Name** and **Generate selected name** now work in the browser editor instead of saying "Naming is not available in the browser yet". The OPSIN Rust port and naming rules run in the editor's own Web Worker and WebAssembly module (`dist/worker/`, 2.3 MB gzipped, which later heavy jobs can share), loaded on the first conversion, so the editor's own module carries none of the OPSIN data and drawing and typing carry on while a name is read. As on the desktop, a request stops after 15 seconds and its heap is capped at 96 MiB (the worker's memory at 128 MiB), and the next request starts a new worker. The parser's resources also take less memory, on the desktop too: 7.5 MiB instead of 33.8 MiB after loading, so a first parse of "caffeine" in the worker peaks at 19.6 MiB instead of 33.9 MiB.

# Clear crystal-file errors in the CLI (#490)

`convert`, `render`, and `analyze` now recognize crystal file paths and reject
unsupported crystal input before reading the file or creating an output.
The error identifies the command and crystal format, lists supported inputs,
and exits with usage status 2. It replaces the misleading SMILES parse error.

This implements the explicit-refusal option in #490. Crystal reading remains
available in the desktop and browser editors. This change does not add crystal
conversion or molecular analysis of distance-derived crystal bonds to the CLI.

The shared application format mapping recognizes CIF, PDB/ENT, VASP,
POSCAR/CONTCAR, XYZ, and extended XYZ, including case variants and VASP
filename prefixes. Supported molecular extensions take precedence:
`POSCAR.mol` remains MOL and `CONTCAR.rsk` remains a native drawing.
`--from auto` still rejects recognized crystal paths; an explicitly selected
supported molecular format can override a misleading filename.

## Validation

Base: `3d80590a`; implementation: `141817f8`. Platform: macOS arm64, Rust 1.99.0 development builds.
Input: the existing `tests/fixtures/crystal/nacl.cif`, unchanged between runs.

| Command                                      | Before                             | After                                                                                    |
| -------------------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| `reshiki --cli convert nacl.cif -o nacl.svg` | Exit 1: `Invalid SMILES at byte 0` | Exit 2: `convert does not support crystal input (cif)` followed by the supported formats |
| `reshiki --cli render nacl.cif -o nacl.svg`  | Exit 1: `Invalid SMILES at byte 0` | Exit 2: `render does not support crystal input (cif)` followed by the supported formats  |
| `reshiki --cli analyze nacl.cif`             | Exit 1: `Invalid SMILES at byte 0` | Exit 2: `analyze does not support crystal input (cif)` followed by the supported formats |

All six invocations wrote no stdout and created no output file. There is no
drawing comparison: argument parsing now rejects these unsupported operations
before the chemistry engine or renderer runs.

The CLI regression suite covers rejection for every recognized crystal
extension and VASP filename form across all three commands, both with inferred
format and `--from auto`. The paths deliberately do not exist, proving that
rejection precedes file I/O. It also covers explicit crystal `--from` values,
supported molecular overrides, molecular filename precedence, and unchanged
SMILES fallback for ordinary `.smi`, `.smiles`, `.txt`, unknown, and
extensionless inputs.

Checks: `cargo test --locked -p reshiki --lib cli::tests::`, focused Clippy with
warnings denied, Rust formatting, and the existing help-output goldens.
The CLI help feeds the generated agent reference and skill CLI reference.

unsupported-format message instead of a SMILES parse error.**

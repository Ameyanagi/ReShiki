# Safari text-field paste (#521)

Command-V now inserts clipboard text into browser captions and Import fields
without replaying the V key after a clipboard permission prompt. Text fields
use their native paste event and the existing input-method text bridge. Canvas
drawing paste retains its existing clipboard path; a pending canvas read is
discarded if focus has moved to a text widget or another page control.

## Diagnosis and regression controls

A separate localhost trace of the published package recorded the native
Safari event order. The clipboard itself and the returned text were correct:

| Relative time | Observation                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------- |
| 0 ms          | Trusted Command-V targets the hidden editor textarea.                                                               |
| 1 ms          | The zero-delay fallback starts `readText()` and takes the held key.                                                 |
| 16,237 ms     | After the user approves Paste, a native paste event carries `CCOC(C)=O`.                                            |
| 16,239 ms     | `beforeinput` carries `insertFromPaste` and the same text, but is cancelled.                                        |
| 16,243 ms     | `readText()` resolves with the correct clipboard text.                                                              |
| 16,244 ms     | A synthetic V reaches the canvas with the expected swapped DOM modifiers; the text field subsequently contains `v`. |

The long interval is the manual permission decision, not an engine benchmark.
The replay also depends on Iced's cached modifier state: winit 0.30.13's web
backend queues a keyboard event before its accompanying modifier update. A
controlled run of the old path inserts the correct text when a matching
modifier keydown is delivered before V; without that control, the same
delayed sequence inserts `v`. The fix removes the text field's dependence on
synthetic shortcut replay rather than changing a timeout.

The native textarea paste handler commits clipboard text through `Ime::Commit`
and cancels native insertion. A second `insertFromPaste` cannot commit it
again. Existing composition handling remains in place. No vendored input or
clipboard code changes are required.

The optional [browser regression script](../../packages/editor/browser-tests/paste.mjs)
runs against the built application. In WebKit 27.2 and Chromium 156 it verifies:

- Delayed clipboard completion, ASCII/Japanese text, repeated and empty pastes.
- A duplicate `insertFromPaste` event does not duplicate the text.
- Composition still commits Japanese text, and a shortcut with no paste event
  cannot type a bare V.
- A canvas read completed after a caption opens cannot insert into that caption.
- Canvas drawing paste still imports ethanol as three atoms and two bonds.

The core test fails on the published base with actual `v` and expected
`caffeine 日本語`, and passes on the fixed build. These scripted events are
regression controls; the real Safari keyboard and system-clipboard checks above
are the primary interaction evidence.

The wasm release build and package tests pass (26 passed; 30 existing optional
CLI-parity tests skipped because `RESHIKI_CLI` was unset). Browser-target Clippy,
workspace library/binary Clippy with all features, workspace formatting and
JavaScript lint/format checks pass. No new Rust integration-test target is added.

Firefox 157 from Playwright 1.64.1 could not launch on this host: it exits with
`Could not find profile folder` before loading the application, under both Bun
and Node with a separate temporary directory. Firefox application behavior is
therefore unverified here.

## Running the optional browser checks

Build with `scripts/build_wasm.sh --test`. From `packages/editor`, start
`bun examples/serve.ts`. The default address is
`http://localhost:8080/examples/paste.html`.

Install the test dependency separately, leaving the application package and
lockfile unchanged:

```sh
mkdir -p /tmp/reshiki-browser-check
cd /tmp/reshiki-browser-check
bun init -y
bun add --dev playwright@1.64.1
bunx playwright install webkit chromium
```

From the checkout root, with the server still running:

```sh
RESHIKI_PLAYWRIGHT_MODULE=/tmp/reshiki-browser-check/node_modules/playwright/index.mjs \
  node packages/editor/browser-tests/paste.mjs webkit chromium
```

`RESHIKI_BROWSER_URL` selects a different server address. Where the Firefox
binary launches, install it with `bunx playwright install firefox` and append
`firefox` to the script's browser arguments. The script's default browser list
includes all three engines.
